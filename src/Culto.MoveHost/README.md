# Culto MoveHost

Hidden x64 .NET 10 worker for **real libobs 33.0.1 + Exeldro Move Transition 3.2.1**. The desktop parent starts it with `CreateNoWindow=true`, `UseShellExecute=false`:

`Culto.MoveHost.exe --pipe NAME --runtime ABSOLUTE_RUNTIME_PATH --width 1920 --height 1080`

The parent creates a duplex, asynchronous, current-user-only named-pipe server first. Shared framing and JSON live in `Culto.Core/ObsMoveProtocol.cs`: one byte type, four-byte little-endian signed payload length, then payload (maximum 64 MiB). Types: Command=1, packed BGRA frame=2, Complete=3, UTF-8 Error=4, Ready=5. Ready/Complete have empty payloads. JSON commands contain `outgoingPath`, `incomingPath`, `durationMilliseconds` (1–60000). PNG paths must be absolute. Dimensions are fixed for the worker's lifetime. Send one command and consume its frames through Complete before sending another. EOF closes the worker; an Error is terminal. A crash closes the pipe and must be reported by the parent.

Initialization loads `bin/64bit/obs.dll` by absolute path and limits dependency lookup to System32 and the two supplied runtime DLL directories. It initializes BGRA output at 30 fps, private scenes and the real `move_transition` source. Required modules are `image-source.dll`, `obs-transitions.dll` and `move-transition.dll`, with their matching `data/obs-plugins` directories and `data/libobs`. Use `scripts/prepare-obs-move.ps1` to prepare the pinned runtime and provenance manifest. Native DLLs remain loaded until worker exit; no OBS executable, frontend application or capture source is launched.

The two inputs are full-frame PNG snapshots, not independently editable scene elements. Move's unmatched-item defaults animate the outgoing/incoming snapshots. Its optional nested frontend transitions and Move filters are not configured. The shipped frontend API library's absent-callback guards are used; no application-wide OBS frontend state is modified. Video output callbacks copy BGRA rows into a bounded two-frame queue; pipe writes never execute on an OBS callback thread. The first frame is actual OBS output. Complete is sent only after native transition progress reaches 1 and a later rendered output frame has been delivered. Watchdogs produce Error, never a synthetic imitation or silent fallback.

Only compilation and pure protocol tests are permitted in the current workflow. **Native initialization, plugin compatibility, GPU rendering and actual Move motion have not been executed or verified.** Runtime permission and an isolated end-to-end test are still required. Keep this process boundary: a native plugin failure must not bring down the desktop UI. libobs and Move are GPL software; retain the runtime's licenses, source/provenance information and comply with distribution obligations.
# Window capture

The worker also accepts `--capture-window` after its existing pipe/runtime/width/height arguments. It reads an `ObsCaptureCommand` and streams fixed-size BGRA frames until the client disconnects. The capture branch does not load image/transition modules and does not open OBS or a projector window.

Capture uses the bundled OBS 33.0.1 `libobs-winrt.dll` Windows Graphics Capture backend directly by HWND. It does not load the `win-capture` module, search by window title, inject hooks, or switch to a different matching browser window. HWND, PID, executable and class are checked before starting, and HWND/PID/class/minimized/visibility state is checked while running. Window title can change as YouTube navigates. Closing or minimizing the selected window produces an explicit error; protected content may remain unavailable.

The capture frame pool is created in OBS' graphics callback, on the thread with OBS' WinRT dispatcher. `obs_add_raw_video_callback` activates native rendering for capture. Only frames rendered after the first real WGC texture are delivered. Pixel cropping and aspect-fit scaling happen on the GPU, with black margins. Output runs at 30 fps. Audio is deliberately excluded from this worker: the application controls the selected browser's original audio to avoid duplicate playback on its local output.

Primary API references: [OBS WinRT capture exports](https://github.com/obsproject/obs-studio/blob/33.0.1/libobs-winrt/winrt-capture.h), [OBS graphics thread](https://github.com/obsproject/obs-studio/blob/33.0.1/libobs/obs-video.c), [core render callbacks](https://docs.obsproject.com/reference-core).
